1. Mapa: DDL, DML y consultas

SQL es el lenguaje para hablar con la base de datos. PostgreSQL es el sistema que lo ejecuta. Los comandos se agrupan por lo que hacen:

GrupoHaceComandos
DDL (definición)Crea o cambia la estructuraCREATE ALTER DROP TRUNCATE
DML (manipulación)Cambia los datos dentro de las tablasINSERT UPDATE DELETE
ConsultasLee datos, no los cambiaSELECT (con JOIN, WHERE, GROUP BY, ORDER BY, LIMIT)

Pregunta clave al leer un enunciado: ¿me piden crear la tabla (DDL), cambiar filas (DML) o mirar datos (SELECT)?

3. CREATE TABLE por dentro

Así se lee una tabla real del LAB4. Cada número se explica abajo.

CREATE TABLE esports.torneo 1(
    id_torneo INT PRIMARY KEY,                      2
    id_juego INT NOT NULL,                         3
    nombre_torneo VARCHAR(80) NOT NULL,
    premio INT NOT NULL CHECK (premio >= 0),       4
    fecha_inicio DATE NOT NULL,
    modalidad VARCHAR(20) NOT NULL CHECK
        (modalidad IN ('Presencial','Online','Híbrida')), 5
    FOREIGN KEY (id_juego) REFERENCES esports.videojuego(id_juego) 6
        ON DELETE RESTRICT ON UPDATE CASCADE               7
);                                                   8
  1. Nombre de la tabla. Con esquema: esquema.tabla. Después del nombre se abre el paréntesis.
  2. Columna = nombre + tipo + restricciones. PRIMARY KEY identifica cada fila: no se repite ni es NULL.
  3. NOT NULL: el dato es obligatorio. Esta columna es además la FK (el torneo siempre es de un juego).
  4. CHECK (condición): rechaza valores que no la cumplen (premio negativo).
  5. CHECK con IN: el valor debe estar en la lista (dominio).
  6. FOREIGN KEY (columna_local) REFERENCES tabla_padre(columna_padre): el valor debe existir en la tabla padre.
  7. Política de la FK: qué hacer si el padre se borra o cambia su clave (sección 5).
  8. Cierre: sin coma después de la última línea, y termina con ;.

Tabla N:M: clave primaria compuesta

CREATE TABLE esports.participa (
    id_jugador INT NOT NULL,
    id_equipo  INT NOT NULL,
    PRIMARY KEY (id_jugador, id_equipo),            -- la PK junta las dos columnas
    FOREIGN KEY (id_jugador) REFERENCES esports.jugador(id_jugador)
        ON DELETE CASCADE ON UPDATE CASCADE,
    FOREIGN KEY (id_equipo) REFERENCES esports.equipo(id_equipo)
        ON DELETE CASCADE ON UPDATE CASCADE
);

Reglas de oro: (1) crea primero las tablas padre y después las hijas; (2) separa con coma cada columna y cada restricción, pero no pongas coma antes del ) final; (3) cada FK necesita REFERENCES.

5. ON DELETE y ON UPDATE

Definen qué pasa con las filas hijas cuando la fila padre se borra (ON DELETE) o cambia su clave (ON UPDATE).

AcciónEfecto sobre las hijasEjemplo del laboratorio
CASCADEEl cambio se propaga: se borran, o toman la clave nuevaBorras un autor y se borran sus libros
SET NULLLa FK de la hija queda en NULLBorras una categoría y sus productos quedan sin categoría
SET DEFAULTLa FK toma su valor DEFAULT. La columna debe tener DEFAULT, si no fallaPedidos vuelven al estado 1
RESTRICTImpide la operación si hay hijasNo puedes borrar un departamento con empleados
Caso con el esquema esports
  • DELETE FROM esports.jugador WHERE id_jugador = 3001; falla: 3001 es capitán del equipo 5001 y equipo.capitan es ON DELETE RESTRICT.
  • DELETE FROM esports.equipo WHERE id_equipo = 5001; funciona y arrastra sus filas de participa y compite, porque ahí es CASCADE.

Dos siempre: insertar una FK con un valor que no existe en el padre se rechaza con cualquier política. Y si no escribes nada, la política por defecto es NO ACTION, que se comporta como RESTRICT.

7. INSERT, UPDATE y DELETE

-- Insertar: primero el padre, después la hija
INSERT INTO autos.propietario (rut, nombre, apellido, ciudad)
VALUES ('8738936-0', 'Diego', 'Muñoz', 'Valparaiso');

-- Actualizar: SIEMPRE con WHERE
UPDATE autos.vehiculo
SET rut = '8738936-0'
WHERE patente = 'HTTP25';

-- Borrar: SIEMPRE con WHERE
DELETE FROM autos.propietario
WHERE nombre = 'Abraham' AND apellido = 'Pérez';
  • Texto y fechas van entre comillas simples; los números, sin comillas ni puntos.
  • Los valores van en el mismo orden que la lista de columnas.
  • Sin WHERE, UPDATE y DELETE afectan todas las filas.
  • La sintaxis es UPDATE tabla SET ... y DELETE FROM tabla .... La diapositiva del LAB3 escribe UPDATE INTO y DELETE tabla, que están mal.

8. SELECT y sus cláusulas

SELECT [DISTINCT] columnas | *       -- 5. qué columnas muestro
FROM tabla                          -- 1. de dónde saco los datos
[JOIN otra ON condición]             -- 2. unir tablas
WHERE condición                     -- 3. filtra filas
[GROUP BY columna]                  -- 4. agrupa
[ORDER BY columna [ASC|DESC]]       -- 6. ordena
[LIMIT n];                          -- 7. corta a n filas

Se escribe en ese orden, pero la base lo resuelve en el orden de los números: primero FROM y JOIN, luego WHERE, GROUP BY, SELECT, ORDER BY y al final LIMIT.

Quiero...UsoEjemplo
FiltrarWHERE con = <> > >= < <=, AND, OR, NOTWHERE precio <= 2000
Quitar repetidosDISTINCTSELECT DISTINCT ciudad FROM cliente
OrdenarORDER BY col DESC (más grande primero) o ASCORDER BY fecha DESC
Las n primerasLIMIT n junto con ORDER BYORDER BY premio DESC LIMIT 5
RenombrarASFROM producto AS p, COUNT(*) AS total

"Los 5 con mayor X" = ORDER BY X DESC LIMIT 5. "Los más recientes primero" = ORDER BY fecha DESC.

9. Agregaciones y GROUP BY

Una función de agregación resume muchas filas en un valor:

FunciónDevuelveSobre la tabla de ventas (2, 4, 7)
SUM(col)La suma13
AVG(col)El promedio4,333
COUNT(*)Cuántas filas hay3
COUNT(col)Cuántas filas tienen col distinto de NULL3
MAX(col) / MIN(col)El mayor / el menor7 / 2

GROUP BY hace el cálculo una vez por grupo:

SELECT c.nombre, COUNT(*) AS cantidad_productos
FROM minimarket.producto AS p
JOIN minimarket.categoria AS c ON p.id_categoria = c.id_categoria
GROUP BY c.nombre;     -- una fila por categoría
  • Regla: toda columna del SELECT que no sea una función de agregación debe aparecer en el GROUP BY.
  • "Por cada X" o "de cada X" en el enunciado anuncia un GROUP BY X.
  • COUNT(*) cuenta filas aunque tengan NULL. COUNT(sponsor) se salta los NULL.
  • Con GROUP BY el resultado tiene una fila por grupo.

10. JOIN

Une filas de varias tablas cuando una condición las relaciona. Casi siempre es clave primaria = clave foránea.

-- Estilo del curso: JOIN explícito
SELECT v.marca
FROM autos.vehiculo AS v
JOIN autos.propietario AS p ON v.rut = p.rut
WHERE p.nombre = 'María' AND p.apellido = 'Peña';

-- Equivalente antiguo (join implícito): funciona, pero el curso pide JOIN
SELECT v.marca
FROM autos.vehiculo AS v, autos.propietario AS p
WHERE v.rut = p.rut AND p.nombre = 'María' AND p.apellido = 'Peña';

Receta para consultas con varias tablas

  1. ¿Qué columnas piden? Escríbelas en el SELECT con su alias: c.nombre.
  2. ¿Qué tablas están en el camino? Incluye también la tabla del medio (la N:M).
  3. Une cada par vecino con ON, PK = FK. Con n tablas necesitas n−1 JOIN.
  4. El filtro va en WHERE. Los ON solo sirven para unir.
-- Nombres de los 3 productos más vendidos (4 pasos en una consulta)
SELECT p.nombre, SUM(d.cantidad) AS total_vendido
FROM minimarket.producto AS p
JOIN minimarket.detalle_venta AS d ON p.sku = d.sku
GROUP BY p.nombre
ORDER BY total_vendido DESC
LIMIT 3;

Si olvidas un ON, cada fila se combina con todas las de la otra tabla y el resultado se multiplica sin sentido.

11. Subconsultas

Un SELECT dentro de otro. Sirve cuando necesitas un valor o un conjunto calculado antes.

-- El producto más caro (una subconsulta que devuelve UN valor)
SELECT nombre, precio
FROM minimarket.producto
WHERE precio = (SELECT MAX(precio) FROM minimarket.producto);

-- Equipos que no compiten (una subconsulta que devuelve VARIOS valores: IN)
SELECT nombre_equipo FROM esports.equipo
WHERE id_equipo NOT IN (SELECT id_equipo FROM esports.compite);

-- Una subconsulta como tabla: lleva alias obligatorio
SELECT COUNT(*) FROM (SELECT DISTINCT ciudad FROM minimarket.cliente) AS ciudades;
  • Un valor: =, >, etc. Varios valores: IN / NOT IN.
  • Para "el más caro", también sirve ORDER BY precio DESC LIMIT 1. Si hubiera empate, la subconsulta con MAX devuelve todos los empatados y LIMIT 1 solo uno.

12. Vistas

CREATE OR REPLACE VIEW equipos_con_torneo AS
SELECT DISTINCT e.nombre_equipo
FROM esports.equipo AS e
JOIN esports.compite AS c ON e.id_equipo = c.id_equipo;

SELECT * FROM equipos_con_torneo;   -- se usa como una tabla

Una vista es una consulta guardada con nombre. No almacena datos: cada vez que la lees, se ejecuta el SELECT y muestra los datos actuales.
